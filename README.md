# ST-WorldBook-Opt

SillyTavern 原生世界书缓存优化扩展。独立实现，不依赖酒馆助手、不加载第三方远程脚本、无需构建或 npm 安装。

**v0.3.0 新增魔法棒“请求输入差异（免费预览）”：上次真实发送的消息输入 vs 当前输入框内容的受限模拟。207项测试/用例通过，模拟界面流程已验证；仍需在你的酒馆版本中实际验收。**

世界书优化逻辑未改变。真实缓存收益仍取决于提示词结构、模型服务商及实际命中情况。

## 安装

仓库当前为公开状态，可直接在酒馆扩展管理中使用仓库地址安装。下面的私人仓库认证步骤仅在仓库以后改为私人时适用；云酒馆也需要能访问 GitHub。

### 私人仓库认证（仅在需要时）

仓库地址：`https://github.com/dthcle/ST-WorldBook-Opt`

1. **在运行酒馆服务端的机器、同一个操作系统账号下**，配置能访问本仓库的 GitHub Git 凭据。浏览器登录 GitHub 不等于服务端 Git 已登录。
2. 在那台机器终端验证：
   ```sh
   git ls-remote https://github.com/dthcle/ST-WorldBook-Opt.git
   ```
   应能看到 main 分支，且无需交互登录。使用系统凭据助手，不要把 PAT/密码写入 URL、代码或聊天。
3. 酒馆 → 扩展 → 安装扩展，填写上述仓库地址。安装后刷新页面。
4. 扩展设置 → **WorldBook Opt · 世界书缓存优化** → **打开世界书优化器**。

**兼容条件：** 酒馆支持第三方 ES module 扩展，提供 `worldInfoCache`、`WORLDINFO_UPDATED`、`getRequestHeaders` 和 `AccountStorage`。以官方 release 分支接口核对，未宣称兼容全部历史版本。

较新的酒馆有 `git.backend` 选项：私人仓库需要系统 Git 与已配置的凭据助手；builtin 克隆后端不使用系统凭据助手。必要时在酒馆配置中选择 system 并重启，具体遵循你的版本文档。如果酒馆部署在 Docker、服务器或手机上，需要在**该运行环境**配置认证，本机 Windows 的登录不会自动传过去。

### 手动 Git 安装备用方式

在**已有的**酒馆第三方扩展目录运行（先确认目录）：

```sh
git clone https://github.com/dthcle/ST-WorldBook-Opt.git
```

通常当前账号扩展目录为 `data/<账号handle>/extensions/`，全局目录为 `public/scripts/extensions/third-party/`；以你实际酒馆版本及数据目录为准。不要把项目克隆进角色卡或世界书目录。文件夹根部必须直接包含 manifest.json。

更新可在酒馆扩展管理中点击更新；或在该扩展目录运行 `git pull --ff-only`，随后强制刷新页面。私人仓库更新同样需要服务端认证。

## 使用

1. 先在酒馆导出重要世界书作为独立备份。
2. 关闭世界书编辑器，等待保存完成；不要同时在其他标签页、设备或编辑器修改。
3. 选择一本世界书，生成方案。预览不写入数据，也不执行宏/EJS。
4. 查看每条位置、灯色、角色、深度、冷却的前后差异及风险，手动勾选。
5. 点击应用，再次确认。**本地备份成功才写入，保存后重新读服务器验证。**
6. 保存成功后重新打开酒馆世界书编辑器，不要保留旧编辑界面继续保存。

风险条目默认不勾选。许多有效建议本身有行为风险，所以默认选择0条是正常的；逐条核对后手动选择。不提供不加区分的全选应用。

## 魔法棒：请求输入差异（免费预览）

1. 更新后强制刷新酒馆。在当前单人聊天**正常发送过一次**后，扩展会保留那次实际请求的消息输入。它不会为建立基线自动发模型请求；刷新前的请求无法倒推恢复。
2. 把准备发送的文本写入用户输入框，**不要点发送**。
3. 魔法棒 → **请求输入差异（免费预览）**。
4. 阅读模拟限制，关闭自定义宏/脚本后确认，点击**生成免费预览并对比**。
5. 查看消息 #1 起的顺序对比、第一处变化、字段正文高亮；可切换全部消息、跳到首个差异。

真实基线是浏览器对酒馆 `/api/backends/chat-completions/generate` 的实际POST输入，记录响应/失败状态，**不是服务器转发到提供商后的最终报文**。只留最近一份于内存，按当前聊天身份匹配，不存请求头、代理密码、API地址。刷新或清除记录后丢失。

模拟通过官方 `generate('normal', options, true)` 组装消息；因原生dry-run不包含textarea输入，扩展先临时加入虚拟用户消息，在finally恢复已知原始对象和输入框。不调用发送按钮、sendMessageAsUser、generateQuietPrompt或保存聊天。

### 受限范围与安全限制

- 仅单人 Chat Completion 普通文本；正在生成/预览、群聊、空输入、斜杠命令、待附件、工具调用/结构化输出、系统消息合并会拒绝预览。
- 预检当前聊天、角色、提示词、启用世界书中的宏。写变量/随机/未知宏与EJS拒绝；只允许列明的只读原生宏候选。允许的时间宏本身仍可能产生变化。
- 原生dry-run仍可能有状态副作用；本扩展恢复已知的聊天、metadata、extension prompts/settings、输入框及提示管理字段，不声称能完全回滚酒馆所有内部闭包状态。
- 预览跳过生成/世界书事件插件，原生生成拦截器也不会执行，所以记忆、向量、MVU/EJS等第三方贡献不能当作已精确模拟。确认前请关闭自定义宏/脚本，不要在预览过程中发送或切换聊天。
- 预览同步保护fetch/XHR及新WebSocket，拒绝模型生成、外部和未知网络路由，只允许列明的同源世界书/角色读取及**本地分词端点**；远程分词拒绝。阻断过任何请求则不给出成功结果。
- 网络保护不是针对任意第三方脚本的安全沙箱，不能控制提前保存的原生网络函数、已有socket、worker或已经在途的请求。不适用于未审计的自定义宏环境。
- 粘附/冷却/概率、外部强制激活、附件、RAG与提供商后端转换等，可能使实际下一次请求不同。无法保证所有插件环境的无副作用与精确预测。

比较按**相同消息索引**从头到尾执行，不为了让结果好看而重排/对齐中间消息。中间插入后后续行也会显示不同，尾部额外行显示新增/删除。对象字段规范化排序、数组顺序保留；字段位置是UTF-16单元偏移，前缀也是规范化JSON字符度量，**不是token数量或真实缓存命中率**。角色/name/多模态结构/工具调用等消息字段也参与比较。

## 原理与规则

服务端提示词缓存一般要求稳定前缀。本扩展尝试减少每轮触发和插入位置的变化，**不压缩正文，不保证命中缓存、降低 token 或省钱**。

| 条目 | 建议 |
| --- | --- |
| 可处理条目冷却 | 设为0 |
| 动态宏、EJS、MVU、变量等候选 | user D0，保持灯色 |
| 静态指定深度0–9 | user D0；按 order 降序位于动态候选前的绿灯建议转蓝灯 |
| 静态指定深度10+ | 蓝灯 user D9999 |
| 普通主提示词前/后静态绿灯 | 保持位置，转蓝灯 |
| 普通主提示词前/后静态蓝灯 | 保持位置及灯色 |

这是保守版本，不是原脚本逐字迁移：禁用条目、作者注释/示例/outlet专用位置、概率/分组/角色过滤/递归/延迟等特殊行为整体跳过。未知扩展字段不保证能识别。全部宏（包括角色名称宏）保守标为动态候选，可能有误报。

**D9999 不保证置于全部提示之前**，实际位置取决于聊天长度、上下文裁剪、提示词配置及酒馆版本。只应用完整方案中的部分动态关联建议时，前后关系可能不成立。

**保留 originalData 原始导入数据的世界书仅允许预览**。因为源格式映射不可靠，原生字段修改可能在后续导出时还原旧值；本版禁止应用，不自动删除原始数据。需使用原生格式世界书。

## 前后对比到底对比什么？

- 每条配置的优化前 / 优化后。
- 已勾选方案的常驻条目数、常驻正文 token 字符估算。
- 估算方法：每条 `ceil(ASCII码点/4 + 其他码点/1.5)`，不含包装和模板展开。
- **不是**真实模型请求、实际激活条目、API usage、命中率或费用对比。本版不监听模型网络请求。

## 备份与并发限制

- 备份保存在酒馆 AccountStorage，按酒馆账号隔离，位于当前浏览器存储。
- 最多保留最近20份；失败写入或最后一次冲突检查失败也可能留下一份备份。
- 存储满、持久化失败会阻止保存。清除浏览器数据或换浏览器会丢失备份，建议用“导出备份”保留重要版本。
- 恢复会覆盖整本书，恢复前也备份当前版本。导出的原生 JSON 可通过酒馆导入恢复。
- 保存前两轮检查服务器和本地酒馆缓存变化，拒绝陈旧方案；保存后校验服务器结果。
- 酒馆接口没有 compare-and-swap；仍无法完全防止其他客户端恰好在读写间隙覆盖数据。不要同时编辑。

## 隐私

世界书内容仅用于浏览器本地分析、账号浏览器备份、以及现有酒馆同源世界书读写接口。无遥测、无额外模型 API、无远程脚本加载。仓库不包含登录脚本、访问令牌或用户世界书。

## 开发与测试

Node.js 18+，无外部依赖：

```sh
npm test
node dev/server.mjs
```

然后访问 `http://127.0.0.1:18765`。预览操作只修改内存中的模拟世界书，不连接真实酒馆；这不是酒馆安装验收。

在限制子进程通信的环境，可分别单进程执行：

```sh
node tests/engine.test.js
node tests/transaction.test.js
node tests/adapter.test.js
```
