# ST-WorldBook-Opt

SillyTavern 原生世界书优化与请求差异诊断扩展。无构建步骤、无额外依赖、不加载远程脚本。

**v0.5.4 修正对比语义：BASE 只来自上次真实请求 N−1，右侧预览当前聊天即将发送的 N。移除手动模拟基准与旧轮重放，增加最近两次真实请求差异。默认空文本不读输入框，可选只读草稿；都不清空草稿、不新增持久聊天消息、不调用模型。**

v0.5.1 支持整数和 UUID 两种世界书条目 UID，原键、原 UID 与引用保持不变；不重新编号。这是格式兼容修复，与绿灯/蓝灯切换无关。

v0.5.0 已修复捕获时序，而不只是差异显示。 旧版在提示词事件内过早克隆，可能记录第三方压缩脚本尚未清理的中间消息。现在在酒馆调用 `window.fetch` 的最终 JSON 边界观察正常请求，并阻断预览的模型请求。原世界书优化规则未改变。

## 安装与更新

酒馆 → 扩展 → 安装扩展：

```text
https://github.com/dthcle/ST-WorldBook-Opt
```

仓库目前公开。安装此版本后强制刷新页面，扩展设置里应显示版本 **0.5.4**。

如果以后改为私人仓库，运行酒馆的服务器/容器账号必须配置 GitHub 凭据。浏览器登录不能代替服务器 Git 登录；不要把令牌写入安装 URL。

手动安装：在已有的账号扩展目录 `data/<账号handle>/extensions/` 或全局第三方扩展目录 `public/scripts/extensions/third-party/`（以你的酒馆版本为准）运行：

```sh
git clone https://github.com/dthcle/ST-WorldBook-Opt.git
```

更新可使用扩展管理或在扩展目录执行 `git pull --ff-only`，随后强制刷新。

## 世界书优化

扩展设置 → 展开 **WorldBook Opt · 世界书缓存优化** → **打开世界书优化器**。

1. 先导出重要世界书作为独立备份。
2. 关闭世界书编辑器并等待保存，不要同时从其他设备/页面修改。
3. 选择世界书，生成方案，逐条查看前后配置与风险。
4. 勾选要修改的条目，再次确认应用。自动本地备份成功才写入，写后重新读服务器验证。
5. 重新打开酒馆世界书编辑器查看结果。

| 条目 | 默认建议 |
| --- | --- |
| 可处理条目冷却 | 设为0 |
| 动态宏/EJS/MVU/变量候选 | user D0，保持灯色 |
| 静态指定深度0–9 | user D0；按 order 降序位于动态候选前的绿灯建议转蓝灯 |
| 静态指定深度10+ | 蓝灯 user D9999 |
| 普通 before/after 静态绿灯 | 保持位置，转蓝灯 |
| 普通 before/after 静态蓝灯 | 保持位置及灯色 |

禁用条目、作者注释/示例/outlet位置、概率/分组/角色过滤/递归/延迟等特殊行为保守跳过。带 `originalData` 的导入世界书仅预览，不自动删除源数据或冒险修改源格式。

检测为启发式，不保证识别全部宏/扩展字段；角色、深度、触发条件、冷却的改变可能影响角色表现。D9999 不保证置于全部提示之前，输入增量和缓存收益取决于实际上下文和提供商。**不是无损压缩、不保证缓存命中或省钱。**

世界书方案的 token 仅为每条 `ceil(ASCII码点/4 + 其他码点/1.5)` 的字符估算，不含包装、宏展开，不是假造的 API usage。

## 魔法棒：请求输入差异

1. 扩展加载后，正常发送的第 N−1 次真实请求自动成为 BASE。右侧使用**当前聊天历史（含上一轮模型回复）**组装下一次 N，不重放 N−1。
2. 打开魔法棒或扩展设置里的 **请求输入差异**。默认 **预览下一次：空文本（不读输入框）**：不追加新正文，可检查当前历史和世界书组装；它不是你包含草稿的完整下一次请求，也不应用 `send_if_empty`。
3. 若要包含准备发送的正文，选择 **预览下一次：当前草稿（只读）**。只读一次草稿，在临时聊天副本中加入该文本；不修改/清空输入框、不调用用户发送接口、不保存聊天。普通发送的用户 regex/宏、附件等处理并未完整复现，因此仍是近似。
4. 点击 **预览 N 与上次真实请求对比**。每次预览都和真实 N−1 比，不会覆盖 BASE，不存在“把模拟设为基准”。没有真实记录时只能查看组装，明确不能做 N−1→N 比较；从聊天文本无法可靠还原过去的完整请求。
5. 正常发送 N 后，自动保留最近两次真实请求，点击 **查看最近两次真实请求差异** 可直接查看真实 N−1→N，**不额外发送请求**。后续真实发送向前滚动，历史不会累计。
6. 按消息顺序查看角色、正文和首差位置；可显示相同行、跳到首差。**实际缓存命中率需提供商真实 usage/cached tokens**，前缀稳定仅是缓存复用线索，不能由本工具字符数计算实际命中率。

例如：第 N−1 次发送含历史 H 和用户 U；收到回复 A 后，下一次应比较 `H+U` 与 `H+U+A+下一条草稿`。新增回复和草稿通常是末尾增量；本工具帮助定位更早前缀为什么发生变化。旧版“重放上次用户内容”和“手动模拟 BASE”适合另一种设置实验，不符合此缓存排查用途，现已移除。

**模拟不等于最终发送报文。** 它是酒馆 dry-run 组装结果；普通发送拦截器、SETTINGS_READY、系统消息合并与世界书粘附/冷却可能不走同样流程。对比真实记录时会明确标记来源，不能把所有差异都归因于世界书优化。

### 正确的捕获点

- **真实记录**仍观察酒馆把正文 `JSON.stringify` 后调用 `/api/backends/chat-completions/generate` 的 POST fetch 参数：此时 `CHAT_COMPLETION_SETTINGS_READY` 的 awaited listeners 已完成。不在某个早期事件监听器里冒充最终正文。
- 正常请求只有真实调用传输并取得成功 HTTP 响应才建立基线；quiet/impersonate、已取消和失败请求不冒充“上次实际请求”。成功 HTTP 响应不等于流已完成或提供商已计费。
- **模拟快照**保留 `GENERATE_AFTER_DATA(data, true)` 的对象引用，等待原生 dry-run 完全结束后才克隆 `data.prompt`，包含后注册的 awaited listeners。没有达到最终 fetch，不冒充最终正文。
- `dryRun` 是 Generate 的第三个位置参数，不是 `{dryRun:true}` 选项。缺少已验证接口、事件缺失/重复、组装失败或身份变化时拒绝；绝不改用普通发送。
- 模拟期间另有 fetch 防护：标准模型请求、外部请求、已知写入请求与远程 tokenizer 被拒绝。允许本地 tokenizer 和世界书读取。不是依靠停止按钮取消已发送的模型请求。
- 魔法棒与设置按钮共用 runtime，模拟不会覆盖真实记录。超时/关闭后保留防护与副本直到生成 Promise 结束，迟到请求仍阻止；若第三方流水线一直挂起，请刷新页面。

### 限制与副作用

只支持标准浏览器单人 Chat Completion。原生 Tauri/自定义传输与群聊不支持。空文本预览不读取输入框，草稿命令和待发送附件不会执行/上传。只读草稿预览遇到斜杠命令或待发送附件会拒绝，不冒充完整发送。

模拟不调用用户发送/删除/保存消息接口。酒馆组装使用临时聊天副本，完成后恢复原消息对象；聊天元数据与公开扩展提示词也使用副本并恢复。临时替换仍发生在酒馆共享数组中，并非完全隔离的执行环境；模拟时不要发送或切聊天。若切聊天复用了数组，优先保留新聊天，不拿旧数据覆盖它。

**dry-run 不是纯函数**：会运行宏、世界书事件和部分插件；随机概率、时间宏、粘附/冷却等会造成差异，强制激活的世界书私有队列可能被消费。无法回滚任意插件私有状态、全局变量或已经安排的异步保存。请先备份，勿将它当作完全无副作用沙箱。

防护只覆盖当前 `window.fetch`：不能控制旧的原生 fetch 引用、worker/socket/XHR、jQuery.ajax、计时器或未知本地代理接口。仅在可信标准酒馆环境使用；不能保证任意第三方插件都无网络/无费用/无副作用。模拟允许酒馆本地世界书读取和 tokenizer 调用，并不是“整个页面零 HTTP”。

真实记录是酒馆调用 window.fetch 时的正文，不覆盖下游包装器、酒馆后端或提供商改写。不会偷偷删除临时标记。模拟与真实基准都如实标注来源。

### 文本差异统计

消息数组保持原顺序，不为对齐而重排。字段正文采用**分段 patience + 有预算 Myers**，在重复行中保留共同内容，不再用旧版全局唯一行加粗暴成块替换。

显示删除行数、新增行数、相同行数及展示区段；一个替换同时计删除和新增。展示区段数量依赖对齐选择，不是唯一真值；不保证所有输入都达到全局最小编辑解。预算耗尽时明确标记近似回退。

字符前缀是规范化 JSON 的 UTF-16 单元，不是 token 数，更不是缓存命中率。要判断缓存收益仍需提供商真实 usage。前缀稳定只是命中的必要条件之一。

### 修正先前误判

`TH_SQUASH_WI` 是第三方压缩脚本的内部包裹标记，可能在后续处理时被去掉。**旧版看到随机标记，不足以证明它真的发给模型，更不能据此称它“缓存杀手”。**

此前“922行就是真实差异、近一半都是假差异”的结论也不严谨：把不同对齐算法与不同计数口径混在一起比较。新回归以合成重复行及独立 Git 结果验证；用户提供的原文只在本地核验，未上传。

## 备份与隐私

世界书备份位于当前酒馆账号的浏览器 AccountStorage，最多20份，清理浏览器数据或换设备会丢失，重要备份请导出。恢复覆盖整本书，也先备份当前版本。失败或冲突检查也可能留下备份。

保存前两轮检查服务器/酒馆缓存变化，写后验证，但服务器无 CAS，不能完全防止另一客户端恰好在检查后覆盖。不要同时编辑。

最近两次已获酒馆后端成功 HTTP 响应的真实请求仅在本页内存保留，刷新即丢失；不累计完整历史。发送前预览只使用最新真实记录为 BASE，发送后可读最近真实请求对。按聊天身份隔离；异步读取、响应乱序及清除记录的旧在途响应不会误归属或复活旧基线。

只选择 messages/model/source/tools等对比字段，不保留请求头、代理密码或完整配置正文。无遥测，无额外模型 API；仓库不含登录脚本、令牌、用户原文或世界书。

## 开发与验证

Node.js 18+，无外部依赖：

```sh
npm test
node dev/server.mjs
```

- `/dev/preview.html`：优化器样式和折叠入口。
- `/dev/exact-capture.html`：使用真实模块的内存模拟。验证真实 N−1→下一次 N、只读草稿、真实连续请求对、晚处理、预览不增加模型传输、原聊天对象恢复。
- `/dev/menu-check.html`：原生菜单字号/行高/图标位置及主题缩放对齐验证（离线图标占位，不是假装加载了酒馆字体）。
- `?nobaseline=1`：无基线分支；`?compact=1`：窄容器样式验证。

这些是 mock 流程，不是假装已在你的酒馆/手机上验收。测试包括超时迟到发送、stop接口失败、销毁挂起、重复入口、Request正文读取时切聊天/clear、撤回身份与保存，以及重复行对齐预算。
